# Project-template HOW-TO

## Purpose
- High-level workspace guide. Explains how the template is organized and how teams should use it.

## Top-level structure
- management/ — product, charter, PRD, meeting notes, sprint reviews
- engineering/ — RFCs, TRDs, designs, testing, bug log
- README.md — one-line intro and pointers

## How to get started
1. PM: fill project-charter.md and prd.md in management/.
2. Tech Lead: draft TRD in engineering/ and open necessary RFCs.
3. Team: use the DASHBOARD.md files to find next steps and owners.

## How & when to use
- Use this template at project start to document decisions and create a single source of truth.
- Update docs as decisions are made; keep "last updated" headers on each file.

## Maintenance
- Keep links alive; use relative links to files in this repo.
- Weekly: PM and Tech Lead should do a quick sync and update DASHBOARDs.
- Quarterly: archive old meeting notes and mark deprecated docs.

## Hello note
- Hello! This is the project-template workspace. Open management/DASHBOARD.md for product context or engineering/DASHBOARD.md for technical context.
